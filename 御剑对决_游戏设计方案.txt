一、游戏概述
----------------------------------------------------------------
名称（暂定）：御剑对决
备选名：飞剑争锋 / 一剑攻防 / 剑阵对决  [?]

类型：回合制策略卡牌（一攻一防）
题材：东方修仙 / 飞剑（剑修）
平台：微信小游戏
渲染：原生 Canvas / WebGL（不使用游戏引擎）
后端：微信云开发（云函数 + 数据库 + 存储）
目标用户：喜欢轻度策略、修仙题材、碎片化对战的玩家
单局时长：3~6 分钟 [初值]

核心一句话：
  皇室战争式的卡牌策略，改为"一攻一防"回合制——你一招我一招，
  攻方御剑破阵，守方布阵拦截，单局双方各攻守一次决胜负。

----------------------------------------------------------------
二、核心玩法：一攻一防 回合制
----------------------------------------------------------------
2.1 角色与目标
  - 攻方：操控飞剑/剑诀，沿路径推进，目标是摧毁守方"本命剑冢"。
  - 守方：布置剑阵/拦截飞剑，目标是撑满回合数或耗尽攻方攻势。
  - 单局分上下半场，双方各攻守一次，按"摧毁度"定总胜负。

2.2 回合流程（你一招我一招）
  1) 开局：双方剑气槽清零，确定先后手（随机/掷骰）[?]。
  2) 每回合开始：剑气槽回复（+X），上限随回合数缓增。
  3) 攻方先出招：从手牌选一张（飞剑推进 / 剑诀法术），消耗剑气。
  4) 守方后出招：选一张（布剑阵 / 拦截飞剑 / 反制剑诀），消耗剑气。
  5) 结算：飞剑沿路径移动一步并与接触的剑阵交战，伤害结算。
  6) 进入下一回合，交替进行，直到半场结束条件触发。
  7) 上下半场交换攻守，结算总摧毁度，判定胜负。

2.3 半场结束条件（满足其一）
  - 攻方摧毁本命剑冢 → 攻方该半场胜利
  - 达到回合上限（如 12 回合）→ 按剑冢剩余血量计摧毁度 [初值]
  - 攻方剑气耗尽且手牌无可出 → 提前结束 [?]

2.4 胜负判定
  - 总摧毁度高者胜；平局则看剩余剑气/先手等次级条件 [?]。

----------------------------------------------------------------
三、主题包装
----------------------------------------------------------------
  - 剑气      = 费用资源（类似圣水/elixir），每回合回复
  - 飞剑/剑灵 = 攻方进攻单位（不同剑种，攻防属性各异）
  - 剑阵/阵眼 = 守方防守建筑（拦截、减速、范围、反伤等）
  - 剑诀      = 法术大招（万剑归宗、剑气纵横、禁锢等）
  - 本命剑冢  = 守方核心，被摧毁即半场失败
  - 境界      = 养成/段位包装（练气、筑基、金丹、元婴…）[可选]

----------------------------------------------------------------
四、系统设计
----------------------------------------------------------------
4.1 卡牌系统
  - 卡组分攻守两套：攻方卡组（飞剑+剑诀）、守方卡组（剑阵+拦截飞剑）。
  - 单局携带卡组上限 8 张 [初值]，每张可重复携带（带数量）[?]。
  - 手牌：每回合从牌库抽 1 张，手牌上限 5 张 [初值]。
  - 卡牌稀有度：凡品 / 灵 / 宝 / 仙（影响养成成本与强度上限）。

4.2 剑气费用系统
  - 剑气槽上限：开局 5，每回合 +1，封顶 10 [初值]。
  - 每回合回复：+3（不超过上限）[初值]。
  - 卡牌消耗：飞剑 2~6、剑阵 2~5、剑诀 4~8 [初值区间]。

4.3 地图与路径
  - V1：单路棋盘（攻方底端 → 守方剑冢顶端），共 N 格 [?]。
  - 飞剑每回合前进 1 格（受减速剑阵影响）。
  - 剑阵布置在格子上，拦截经过的飞剑。
  - 后续可扩展多路 / 河流 / 高低差 [V2+]。

4.4 攻守轮换
  - 上半场：A 攻 B 守；下半场：B 攻 A 守。
  - 摧毁度 = 对方剑冢造成的伤害比例。
  - 两次半场摧毁度相加定胜负。

4.5 养成系统（V1.5+，先占位）
  - 飞剑/剑灵升级：升星、升阶，提升属性与解锁技能。
  - 剑诀强化：等级提升效果。
  - 剑派/境界：玩家整体成长线，解锁卡牌与关卡。
  - 资源：剑魄（养成货币）、灵石（高级货币）[?]。

六、数值框架（初稿，需平衡）
----------------------------------------------------------------
  - 剑气槽：开局 5，每回合 +1 上限，封顶 10；每回合回复 +3。
  - 半场回合上限：12 回合 [初值]。
  - 本命剑冢血量：30 [初值]。
  - 摧毁度 = 造成伤害 / 剑冢血量 × 100%。
  - 单局总时长目标：3~6 分钟。
  - 抽牌：每回合抽 1，手牌上限 5。
  - 先手劣势补偿：后手首回合多 +1 剑气 [?]。

  [待平衡]：飞剑 vs 剑阵 的费用/血量曲线、流派强度、先后手平衡。

----------------------------------------------------------------
七、变现设计（混合变现）
----------------------------------------------------------------
7.1 广告变现
  - 每日宝箱：看激励视频加速开启 / 额外宝箱。
  - 双倍奖励：对局结算后看视频获双倍剑魄。
  - 续战复活：半场失败时看视频重获一次出招机会（限 1 次）[?]。
  - 每日体力/挑战次数：看视频补充 [?]。

7.2 内购变现
  - 通行证（Battle Pass）：赛季任务 + 奖励轨道。
  - 飞剑/剑灵皮肤：纯外观 + 部分特效。
  - 剑诀/卡牌礼包：加速收集。
  - 灵石（高级货币）：购买皮肤/通行证/资源。
  - 月卡：每日灵石 + 经验加成。

7.3 设计原则
  - 不卖数值（PvP 公平），内购以外观/进度加速为主。
  - 广告为可选，不强制；免费玩家可通过广告获取资源。

----------------------------------------------------------------
八、技术方案
----------------------------------------------------------------
8.1 前端（原生）
  - 渲染：Canvas 2D 起步（回合制 UI 简单），后期可迁 WebGL。
  - 引擎：不使用第三方引擎，自研轻量框架。
  - 模块：渲染循环、场景管理、资源加载、输入、音频、UI、状态机。
  - 包体控制：微信小游戏主包 < 4MB，分包加载。

8.2 后端（微信云开发）
  - 云函数：匹配、对战校验、结算、防作弊。
  - 数据库：用户档案、卡组、背包、战绩、排行榜。
  - 存储：卡牌图、特效、配置表。
  - 对战模式：
      V1 回合制 → 可异步（存回合状态 + 回放），服务器轻量。
      V2 实时PVP → WebSocket + 状态同步/帧同步，开发重。

8.3 社交与传播
  - 开放数据域：好友排行榜、群排行、好友挑战。
  - 分享：分享对局回放、挑战好友、求助。
  - 公众号/服务通知：赛季结算、活动推送 [?]。

8.4 防作弊
  - 回合制：服务端权威校验每步合法性，前端只做表现。
  - 实时PVP：服务端校验关键操作，异常检测。

----------------------------------------------------------------
九、版本规划
----------------------------------------------------------------
9.1 V1.0 MVP（回合制，先行上线）
  - 原生工程骨架（渲染/场景/资源/输入/UI）。
  - 单路棋盘 + 攻守轮换 + 回合流程。
  - 6 张飞剑 + 4 个剑阵 + 4 个剑诀 + 2 个拦截飞剑（精简版）。
  - 剑气费用系统 + 抽牌。
  - 简单 AI 守方（PvE 先验证玩法）。
  - 胜负结算 + 摧毁度。
  - 暂不做：账号、云开发、分享、养成、商城、PvP。

9.2 V1.5（社交 + 轻养成）
  - 微信登录 + 云开发存档。
  - 异步 PvP（挑战好友布阵 + 回放）。
  - 开放数据域排行榜 + 分享。
  - 基础养成（飞剑升级、剑派境界）。
  - 混合变现接入（广告 + 通行证）。

9.3 V2.0（实时 PVP）
  - 实时对战（WebSocket + 状态同步）。
  - 匹配系统 + 段位赛。
  - 更多卡牌 + 流派 + 平衡调整。
  - 赛季 + 锦标赛。

十一、风险与对策
----------------------------------------------------------------
  - 玩法深度不足 → 通过流派/剑诀/随机事件增加策略层。
  - 回合制节奏拖沓 → 限制单回合思考时间（如 20s）[?]。
  - 原生开发效率低 → 自研轻量框架 + 配置驱动卡牌数据。
  - 实时PVP 成本高 → 严格按 V2 规划，V1 先用回合制异步验证。
  - 美术资源 → 先用占位图，验证玩法后再投入正式美术。
